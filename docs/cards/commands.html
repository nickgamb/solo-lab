Commands

The cluster

#Run thisDoes
1
kind get clusters
 Lists kind clusters.
2
docker ps --format '{{.Names}}\t{{.Status}}'
 Lists running containers and their status.
3
kubectl --context kind-solo-lab get nodes -L topology.kubernetes.io/zone
 Lists the nodes, with each node's zone.
4
kubectl --context kind-solo-lab get ns -L lab.solo.io/party,istio.io/dataplane-mode
 Lists namespaces, with each one's party and mesh mode.
5
kubectl --context kind-solo-lab get pods -A
 Lists every pod.

Topology: the mesh

#Run thisDoes
1
istioctl --context kind-solo-lab ztunnel-config workloads
 Lists the workloads ztunnel knows, with node, address and waypoint.
2
istioctl --context kind-solo-lab ztunnel-config certificates --node solo-lab-worker
 Lists the certificates ztunnel holds on a node.
3
istioctl --context kind-solo-lab waypoint list -A
 Lists the waypoints.
4
kubectl --context kind-solo-lab get authorizationpolicy -A
 Lists every authorization policy.
5
kubectl --context kind-solo-lab get serviceentry -A
 Lists the external hosts registered in the mesh.

Traffic

#Run thisDoes
1
kubectl --context kind-solo-lab -n agentgateway-system logs deploy/ai-gateway -f | grep request
 Follows the AI gateway's access log.
2
kubectl --context kind-solo-lab -n agentgateway-system logs deploy/ai-gateway -f | grep request | grep mcp.tool.name
 Follows the MCP calls in the AI gateway's access log.
3
kubectl --context kind-solo-lab -n agentgateway-system logs deploy/ai-gateway | grep -o 'continuity.decision="[^"]*"'
 Prints the assurance decisions the AI gateway logged.
4
make xaa-logs SINCE=2h
 Collects the Cross App Access logs for a time window.
5
kubectl --context kind-solo-lab -n istio-system logs ds/ztunnel --since=5m | grep -i -E "deny|rbac"
 Prints connections ztunnel refused in the last five minutes.

Identity Continuity

#Run thisDoes
1
kubectl --context kind-solo-lab get idc -A
 Lists the IdentityContinuity resources and their active IdP.
2
kubectl --context kind-solo-lab get idc sterling-vance -n sv-identity -o jsonpath='{range .status.tiers[*]}{.name}: {.reason} {.message}{"\n"}{end}'
 Prints each IdP's health.
3
kubectl --context kind-solo-lab get idc sterling-vance -n sv-identity -o jsonpath='{.status.transitions}' | jq
 Prints the failover and failback history.
4
kubectl --context kind-solo-lab get events -n sv-identity --field-selector involvedObject.name=sterling-vance
 Lists the chain's events.
5
kubectl --context kind-solo-lab get authorizationpolicy -A -l continuity.lab.solo.io/tier -o custom-columns='NAMESPACE:.metadata.namespace,POLICY:.metadata.name,IDP:.metadata.labels.continuity\.lab\.solo\.io/tier,CUT BY:.metadata.annotations.continuity\.lab\.solo\.io/cut-by'
 Lists the simulated-outage policies, with the IdP and who applied each.
6
kubectl --context kind-solo-lab get lease continuity.lab.solo.io -n sv-identity -o jsonpath='{.spec.holderIdentity}'
 Prints which controller replica holds the leader lease.
7
kubectl --context kind-solo-lab get idc sterling-vance -n sv-identity -o json | jq -r '.status.tiers[] | .name as $n | .trust.checks[]? | [$n, .name, .result] | @tsv'
 Prints each IdP's trust check results.
8
curl -s https://idp.sterling.lab/realms/sterling-vance/.well-known/openid-configuration | jq '{issuer, authorization_endpoint, token_endpoint, jwks_uri}'
 Fetches the broker's OpenID discovery document.
9
make totp
 Prints the current one-time code (TOTP).

Assurance rules

#Run thisDoes
1
kubectl --context kind-solo-lab get wlp -n sv-identity
 Lists the assurance rules.
2
kubectl --context kind-solo-lab get idc sterling-vance -n sv-identity -o jsonpath='{.spec.assurancePolicy}'
 Prints the default rule.
3
kubectl --context kind-solo-lab get "$(kubectl --context kind-solo-lab api-resources -o name | grep agentgatewaypolicies | paste -sd, -)" -A -o custom-columns='NAMESPACE:.metadata.namespace,POLICY:.metadata.name,EXTAUTH:.spec.traffic.extAuth.backendRef.name,RULE:.spec.traffic.extAuth.grpc.contextExtensions.profile,FAILURE:.spec.traffic.extAuth.failureMode'
 Lists gateway policies with their external authorization settings.
4
kubectl --context kind-solo-lab get svc -A -l continuity.lab.solo.io/assurance-gate
 Lists Services labelled as assurance gates.
5
kubectl --context kind-solo-lab get pods -n sv-identity -l app=assurance-gate -o wide
 Lists the gate's pods and their nodes.
6
kubectl --context kind-solo-lab get validatingadmissionpolicy assurance-gate-fail-closed -o jsonpath='{.spec.validations[*].expression}'
 Prints the fail-closed admission check.
7
kubectl --context kind-solo-lab -n sv-identity logs -l app=assurance-gate --prefix -f | grep '"msg":"decision"'
 Follows the gate's decision log.
8
kubectl --context kind-solo-lab -n sv-identity port-forward svc/assurance-gate 19002:evaluate
 Forwards the gate's evaluate port to localhost.
9
curl -s localhost:19002/v1/evaluate -d '{"continuity": "sterling-vance", "session": {"idp": "contingency", "acr": "aal1"}}' | jq '.rules[] | {name, decision: .session.decision, reason: .session.reason}'
 Asks the gate to evaluate a sign-in against every rule.
