Assurance Rules Demo Card

Fail over to an IdP that proves less, and the workloads that need more fail closed, while the rest keep working. What each needs is a rule; the gate that enforces it also answers what it would decide.

The run-through

#Do thisSay this
1 Observatory Rule builder: Assurance rules Rules What a sign-in must prove to reach each group of workloads, most critical first, and the default rule every rule starts from.
2 Observatory advisor-workspace: Requirements, then Outcome by IdP From the gate AAL2. The firm's Keycloak meets it with a one-time code; the contingency IdP never can. Those answers come from the gate that enforces them.
3 Observatory Enforced at Fail closed The gateway in front of Bob's workspace asks the gate on every call. No answer, no request.
4 Observatory What if: the contingency IdP, acr aal1, Evaluate What if A password-only sign-in: 401 at the workspace and at Ledgerline, with what to ask the IdP for. The console lets it in.
5 Right screen Private window: kagent, sign in at the firm's Keycloak as bob / bob-demo with the code from make totp. Ask Bob's agent to list his clients Allowed A second factor, so AAL2: the workspace answers.
6 Observatory Identity Continuity: Simulate IdP outage on Sterling & Vance (Keycloak) Weaker IdP Sign-in falls to the contingency IdP: a password, nothing more. The banner names the rules now failing closed.
7 Right screen New private window: kagent as bob / bob-demo at the contingency IdP, then ask the agent again Refused Signed in, but the workspace refuses a password-only session. Traffic shows the gate's reason.
8 Observatory Assurance rules: advisor-workspace, mode ReportOnly, Save. Ask the agent again Report only Let through, and Traffic shows would-deny: see a rule's effect before you enforce it.
9 Observatory Mode back to Enforce and Save, then the Code tab As code The same rules as HCL: the default, each IdP, each rule.
10 Observatory Restore IdP network, then undrain what you drained and Save Recovered The broker never stepped anyone up. A stronger sign-in only ever comes from the IdP.
