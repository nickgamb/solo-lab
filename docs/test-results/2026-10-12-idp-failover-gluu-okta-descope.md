# IdP failover in Cross App Access: Gluu to Okta, Descope, 2026-10-12

Each IdP vouches for its own sign-ins (`XAA_VOUCHER=gluu,okta`). Bob signs in through Gluu and reaches Ledgerline with Gluu's ID-JAG. Gluu is cut at S&V's egress; the continuity controller fails over to Okta; Bob signs in through Okta and reaches Ledgerline with Okta's ID-JAG. Descope, Ledgerline's authorization server, trusts both.

| Role | Product |
| --- | --- |
| MCP client (requesting app) | Solo Enterprise for agentgateway (`ai-gateway`), kagent Enterprise (`bob-assistant`), Solo ext-auth (assurance rules) |
| IdPs, ID-JAG issuers | Gluu Flex / Janssen (sterling-idp.gluu.info), then Okta (Cross App Access) |
| Authorization server | Descope, Agentic Identity Hub (Cross-App Access) |
| MCP server | Ledgerline Research behind Solo Enterprise for agentgateway (`mcp-gateway`) |

Settings: `ENTERPRISE_IDP=gluu,okta,keycloak,contingency`, `XAA_VOUCHER=gluu,okta`, `RESOURCE_AS=descope` ([IDPS.md](../IDPS.md)).

| Verified | Evidence |
| --- | --- |
| Before: Gluu active; Gluu signs Bob in and vouches; Descope redeems; Ledgerline answers | 1-6 |
| Gluu cut at S&V's egress; the controller marks it unreachable and makes Okta active (11 s) | 7 |
| After: Okta signs Bob in; the gateway picks Okta as the voucher; Okta issues the ID-JAG; Descope redeems; Ledgerline answers | 8-14 |
| Same Descope server and client for both vouchers; only the ID-JAG's issuer changes | 4, 12 |

Tokens, MCP session IDs, authorization codes and client network details are redacted.
