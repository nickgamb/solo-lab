# Okta to PlainID: Cross App Access, 2026-10-12

Bob signs in to the Solo UI through Okta; his agent calls Ledgerline Research. Okta issues the ID-JAG, PlainID redeems it for Ledgerline's token, Ledgerline's MCP server accepts it.

| Role | Product |
| --- | --- |
| MCP client (requesting app) | Solo Enterprise for agentgateway (`ai-gateway`), kagent Enterprise (`bob-assistant`), Solo ext-auth (assurance rules) |
| IdP, ID-JAG issuer | Okta, Cross App Access (Integrator org) |
| Authorization server | PlainID (ID-JAG grant) |
| MCP server | Ledgerline Research behind Solo Enterprise for agentgateway (`mcp-gateway`) |

Settings: `ENTERPRISE_IDP=okta,gluu,keycloak,contingency`, `XAA_VOUCHER=okta`, `RESOURCE_AS=plainid`, with `LEDGERLINE_PLAINID_ISSUER`, `LEDGERLINE_PLAINID_CLIENT_ID`, `LEDGERLINE_PLAINID_CLIENT_SECRET` and `LEDGERLINE_PLAINID_AUDIENCE` ([IDPS.md](../IDPS.md)). PlainID publishes RFC 8414 authorization server metadata.

| Verified | Evidence |
| --- | --- |
| Okta signs Bob in to the MCP client (OpenID Connect) | 1 |
| Okta exchanges the ID token for an ID-JAG: `aud` PlainID's issuer, `client_id` S&V's PlainID client, `resource`, `scope` `research:read`, `act` the AI agent | 2, 3, 4 |
| The MCP client verifies the ID-JAG (`iss`, `aud`, `typ`, `client_id`, `scope`, lifetime) before presenting it, authenticating with `client_secret_basic` | 4 |
| PlainID validates the ID-JAG and issues an access token: `iss` PlainID, `sub` `bob@sterling.lab`, `scope` `research:read`, `aud` `https://mcp.ledgerline.lab/mcp` | 5 |
| Ledgerline's gateway and MCP server accept PlainID's token for `account_info` and `sector_outlook` | 5, 6 |

Tokens, MCP session IDs, authorization codes and client network details are redacted. Sections 2-4 follow one call (trace `b27cd88c5326cdea092619e0e6768844`).
